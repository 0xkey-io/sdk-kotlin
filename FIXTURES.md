# Cross-language test fixtures

The JSON fixtures under `packages/*/src/test/resources/fixtures/` are generated by calling the built
0xkey JS SDK packages (`@0xkey/crypto`, `encoding`, `api-key-stamper`, `webauthn-stamper`, `core`) at
sdk-js commit `850ef7ef68287d481655b39ab555f181abdc54f8`, not written by hand. The same vectors are used
by the 0xkey Swift SDK, so the three SDKs are checked against one reference implementation.

All keys are synthetic, derived from fixed labels. No production key material, organization or user IDs
are present. Synthetic enclave signer / notarizer keys are passed through `dangerouslyOverride*` parameters.

## Provenance

`original` is the sha256 of the file as committed in the 0xkey Swift SDK; `here` is the sha256 of the file
in this repository. Differences:

- every file: `_meta.generator` and `_meta.generatorCommand` are replaced with a neutral description;
- `constants.json`, `client-signature.json`, `webauthn-stamp.json` (marked *regenerated*): regenerated from
  the same sdk-js commit with neutral sample values (`*Source` descriptions, example e-mail domain and the
  first WebAuthn RP ID). All other vectors in these files are produced by the unchanged generator logic.

`constants.json` keeps the sdk-js `PRODUCTION_ON_RAMP_CREDENTIALS_ENCRYPTION_PUBLIC_KEY` under `zeroxkey` as
generated, although it equals the upstream value; the Kotlin SDK has no on-ramp key and does not read it.
The upstream values (the fork origin in NOTICE) are kept under `upstream` for negative checks only.

The other nine files are data-identical to the Swift SDK copies. Comparisons ignore `_meta` and the
outputs of randomized sdk-js helpers (`sdkJsRandomBundle`, `randomEncrypt`).

## Kotlin to sdk-js direction

`CryptoVectorEmitter` (`packages/crypto`) and `StamperVectorEmitter` (`packages/stamper`) are JVM tests that
run only with `-PvectorOut=<dir> -PvectorFixtures=<dir>`. They write Kotlin-produced artifacts (fresh API-key
stamps, HPKE ciphertexts, credential / import / OTP bundles, all with random keys) as `crypto.json` and
`stamper.json`; merged, they have the same JSON shape as the Swift emitter output and are verified and
decrypted with sdk-js.

## Reproducing

The generator, comparison and verification scripts live in `Scripts/vectors/`. They need Node.js 18+ and an
sdk-js checkout with the `dist` of `@0xkey-io/encoding`, `crypto`, `api-key-stamper`, `webauthn-stamper`,
`attested-stamper` and `core` built (sdk-js is only read):

```bash
# once, in the sdk-js checkout (at the commit above)
pnpm install --frozen-lockfile
pnpm turbo run build --filter=@0xkey-io/crypto... --filter=@0xkey-io/api-key-stamper... --filter=@0xkey-io/webauthn-stamper... --filter=@0xkey-io/attested-stamper... --filter=@0xkey-io/core...

# from this repository's root
SDK_JS_DIR=../sdk-js bash Scripts/vectors/run-all.sh
```

`run-all.sh` regenerates every fixture with `gen-fixtures.mjs` and compares it with the committed copy
(`compare-fixtures.mjs`), runs `./gradlew test`, runs the two emitters and has sdk-js verify their output
(`verify-kotlin-output.mjs`), checks that the sdk-js working tree is unchanged, and ends with `ALL OK`.
Output goes to the git-ignored `build/vectors/`. The `upstream` block of `constants.json` is read from an
upstream JS SDK checkout when `UPSTREAM_SDK_JS_DIR` is set and copied from the committed file otherwise.

CI runs the same script in the `vectors` job against sdk-js commit `850ef7ef68287d481655b39ab555f181abdc54f8`.
